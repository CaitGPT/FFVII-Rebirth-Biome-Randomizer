# Runtime composition work in progress

The 1.0.0 target is a fresh compatible composition each time a cleared existing camp legitimately respawns. These files are a development experiment, not a player release. Automatic lifecycle selection and persistence are implemented as a prototype; native acceptance is in progress.

The native module and Lua component use the installed UE4SS3.0.1 beta c0a8d4c interface. A read-only native test located the live regional EnemyTerritory asset and its frozen content at the observed UObject+0x38 pointer. The first19536bytes have the same layout as the reviewed original export; runtime FName fixups differ as expected. Raw captures remain outside Git.

Identical composition vectors are shared between multiple rows. Editing their elements would change other camps. The guarded experiment instead changes only a selected row's existing frozen relative pointer to another existing two-template vector. Original vectors remain untouched. No allocation, new row, manual enemy creation, count/level change, respawn-timer change or save write is needed for this experiment.

`tools/runtime_layout.py` accepts only the reviewed original SHA256 and generates the name/offset/fingerprint manifest. It embeds no original asset payload. The native validator checks all126 name tokens and the entire normalized structural SHA256. Only four reviewed row references may point to either the native Kalm Fang+Orc vector or the native Mu+Orc vector. All counts, flags, levels, other rows and vector contents remain covered by the checks. A stale expected selection, unknown pointer, changed names, structure mismatch or nonwritable data refuses a write. An uncertain write permanently latches further writes off. Exact full-image readback must equal the prior image except for the requested eight-byte row reference.

The Lua adapter resolves UObjects afresh and retains only string identities across streaming. The pinned UE4SS executor drains on ProcessEvent, which can also run on a loading thread. Binding the first observed thread incorrectly refused later field calls. The corrected guard requires the game's visible UnrealWindow owner thread. Native full-table validation passed with that correction. The earlier manual request wrapper remains in `experimental/runtime-reference-diagnostic/`; the automatic wrapper consumes no developer request files.

A native stale-selection test then caught an argument-binding bug: LuaMadeSimple's getters remove stack values. The setter now consumes the first entry four times and checks all types before consuming anything. A compiled regression covers16 valid camp/choice combinations, missing and string arguments, and out-of-scope targets. The failed native controls made no table changes and remain retained.

The corrected native test passed stale-state refusal, then changed only camp05's reference. Its existing Kalm Fang/two Orc group stayed unchanged and cleared on Hard, with explicit defeat/reward messages. The selection survived fast travel to Oliver's Farm. After the unchanged180-second timer and a return route, exact fresh Mu/two Orc actors appeared at05;23 and29 retained Kalm Fang/two Orcs. Distant scans initially showed only the new Orcs, so an object-inventory snapshot away from a camp does not establish its complete encounter population. The replacement was confirmed on approach. Full native evidence and recording20-41-03.mkv are retained outside Git. This proves a manually requested runtime selection can drive native respawning; automatic random lifecycle acceptance remains pending.

The prototype uses length-framed SHA-256 selection from the seed, camp ID and clear cycle. It requires all three exact members to have positive maximum HP, zero HP and native Dead state before advancing, with a living party outside battle. Absence, streaming, partial kills and defeat do not establish a clear. ReceiveBeginPlay restores selected references early; polling verifies actual groups and ReceiveEndPlay can retain verified death evidence. Another writer or an unexpected group disables the selector. These native lifecycle and initialization timings still require acceptance.

State lives outside game saves at `%LOCALAPPDATA%/FFVIIRebirthBiomeRandomizer/state-v1.json`. Atomic replacement, exact readback, a previous-state backup and a prepared-clear journal protect the four counters. `seed='auto'` creates and reuses a random seed; an explicit different seed starts a new sequence. Corrupt or incompatible state refuses operation. Twenty synthetic Lua 5.4 tests cover the policy, persistence and adapter; they do not prove native behavior.

The first automatic native run passed seed creation, Windows state persistence and full-table validation. It exposed that `GetCharaFromActorName(..., false)` misses ordinary population-manager enemies even while an inventory sees them. A read-only native comparison verified `true` returns the exact live enemy. The corrected adapter and fixture require that path. This failed run made no encounter substitutions and is retained.

The corrected automatic run passed a complete native transition on Hard: exact groups were acquired, a partial clear followed by defeat left all counters at zero, and retry reacquired fresh identities. A subsequent full camp05 clear produced three verified deaths and exactly one automatic cycle commit. After fast travel, the unchanged 180-second timer and a return route, exact fresh Mu/two Orc actors appeared at05. The adapter independently logged `spawn_observed` for cycle1/choice1;23 and29 kept their original Kalm Fang/two Orc actors and counters. No developer table request or overriding data package was active. This passes one automatic clear-to-respawn transition. Restart persistence, initial nonzero selection timing, reverse transitions, remaining arenas, broader pools and final conflict/regression QA remain pending. The temporary battle party used Barret in Cloud's slot and no save was overwritten.
