# Runtime composition work in progress

The 1.0.0 target is a fresh compatible composition each time a cleared existing camp legitimately respawns. These files are a development experiment, not a player release. Automatic lifecycle selection and persistence are implemented as a prototype; native acceptance of the repaired dispatcher is in progress.

## Current callback repair, 2026-11-05

Native5 completed camp23's Mu/two Orc fight on Hard. At00:04:38 UTC, however, UE4SS reported that a transient Lua state had no entry in its instance registry. The queued executor stopped before the last two deaths, leaving23's counter0. The game remained playable and the battle completed; the runtime transition failed. The full recording23-19-59.mkv, log, state, rewards and field capture are retained. This failure blocks release and supersedes earlier scheduler acceptance.

The repair removes LoopAsync, ExecuteInGameThread and Lua RegisterHook from this mod. Its paired native DLL takes exclusive use of the idle persistent main Lua state after script initialization. A synchronous ProcessEvent callback runs only on the verified UnrealWindow thread, with re-entry protection, a 100ms period, bounded stack cleanup and a permanent failure latch. Early territory BeginPlay and verified owned-enemy destroyed EndPlay are delivered synchronously through that same state. The original table, lifecycle and state guards remain. The installed loader's exact exported const name getter bridges its class/struct FName mangling difference from the historical headers. Missing exports disable dispatch.

Twenty-seven synthetic cases pass, including10000 synchronous Lua calls with forced collections, early population preparation and exact-name destroyed/unload handling. These cannot prove native UE4SS state lifetime. Native6 uses DLL c26241e6d3bf431d9be842b150c67a82194032f32bb9fdc946d842a92f5a171f and awaits recorded acceptance.

The known async limitations are described in [UE4SS issue1345](https://github.com/UE4SS-RE/RE-UE4SS/issues/1345). Their relevance to our observed error is an inference supported by the local pinned source and the parent's proven persistent telemetry sampler. We do not patch or replace the user's loader.

## Earlier implementation and evidence

The native module and Lua component use the installed UE4SS3.0.1 beta c0a8d4c interface. A read-only native test located the live regional EnemyTerritory asset and its frozen content at the observed UObject+0x38 pointer. The first19536bytes have the same layout as the reviewed original export; runtime FName fixups differ as expected. Raw captures remain outside Git.

Identical composition vectors are shared between multiple rows. Editing their elements would change other camps. The guarded experiment instead changes only a selected row's existing frozen relative pointer to another existing two-template vector. Original vectors remain untouched. No allocation, new row, manual enemy creation, count/level change, respawn-timer change or save write is needed for this experiment.

`tools/runtime_layout.py` accepts only the reviewed original SHA256 and generates the name/offset/fingerprint manifest. It embeds no original asset payload. The native validator checks all126 name tokens and the entire normalized structural SHA256. Only four reviewed row references may point to either the native Kalm Fang+Orc vector or the native Mu+Orc vector. All counts, flags, levels, other rows and vector contents remain covered by the checks. A stale expected selection, unknown pointer, changed names, structure mismatch or nonwritable data refuses a write. An uncertain write permanently latches further writes off. Exact full-image readback must equal the prior image except for the requested eight-byte row reference.

The Lua adapter resolves UObjects afresh and retains only string identities across streaming. The pinned UE4SS executor drains on ProcessEvent, which can also run on a loading thread.
